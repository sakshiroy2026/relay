Relay is a durable execution runtime for LLM agents: every model call and tool call is appended to a Postgres ledger before it counts. When a worker dies, another one replays the ledger and resumes at the exact step — no model call paid twice, no side effect written twice. You can try the kill yourself, below.

    How the takeover works

    1 · The ledger

    Every step is appended to the steps table before it counts — a model reply is written (with its cost) before it is even judged, because the provider already billed for it. The ledger is the execution log, the event stream, the trace and the eval record at once.

    2 · Lease + fencing

    A claim expires after a lease unless the worker heartbeats. A dead worker needs no cleanup: the timestamp passes and the claim query (FOR UPDATE SKIP LOCKED) reclaims the run. A zombie that wakes up later is fenced by UNIQUE (run_id, step_index) — split-brain protection from a constraint, not a lock service.

    3 · Replay

    The new worker rebuilds the conversation with one ordered SELECT and continues at the next free index. Finished model calls are never re-issued, and write tools are idempotent — a per-call key and a unique constraint make a re-run return the stored result instead of writing twice.
